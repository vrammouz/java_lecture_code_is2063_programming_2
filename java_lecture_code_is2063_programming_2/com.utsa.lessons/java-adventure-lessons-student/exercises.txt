CRITICAL-THINKING PROMPTS
=========================

Use at least one prompt before, during, and after each demonstration. Answers
should cite code and observed output.

C01 TOOLCHAIN
  Predict: Which compiler diagnostic will appear first, and why?
  Explain: How is a compile-time failure different from a runtime failure?
  Extend: Introduce one new syntax error and interpret the diagnostic.

C02 FUNDAMENTALS
  Predict: What happens for an empty name, zero lanterns, or text instead of
  an integer?
  Explain: What information does the declared type give Java before execution?
  Extend: State and enforce a reasonable rule for the lantern count.

C03 DECISIONS
  Predict: Which String comparisons are true before running the trap example?
  Explain: What question does == answer, and what question does equals answer?
  Extend: Test leading spaces, different capitalization, and an unknown command.

C04 LOOPS AND FILES
  Predict: What happens for an empty file or an incomplete three-line record?
  Explain: Which condition guarantees progress toward ending the loop?
  Extend: Avoid rereading the item file for every search. Defend your structure.

C05 METHODS
  Predict: List values printed inside and outside each method call.
  Explain: Why does changing a parameter not reassign the caller's variable?
  Extend: Choose a responsibility to extract into a new method and justify it.

C06 CLASSES
  Predict: How many distinct objects and references exist after construction?
  Explain: Which invariants should Player or Room protect internally?
  Extend: Try an invalid value. Decide whether to reject, correct, or allow it.

C07 COLLECTIONS AND ARRAYS
  Predict: Identify the first invalid index and the resulting exception.
  Explain: When is fixed size an advantage rather than a limitation?
  Extend: Choose ArrayList or an array for exits and defend the decision.

C08 REFERENCES AND EQUALITY
  Predict: Which mutations are visible through aliases and copied references?
  Explain: Distinguish identity, value equality, shallow copy, and deep copy.
  Extend: Define what makes two domain objects equal and test null and wrong-type
  comparisons as well as equal and unequal values.

C09 TEXT PARSING
  Predict: What happens with missing, extra, empty, or nonnumeric fields?
  Explain: Why should validation occur before indexing the parts array?
  Extend: Report an invalid line without losing the valid records after it.

C10 POLYMORPHISM
  Predict: List the files or methods that change when adding one command to
  each design.
  Explain: What behavior is selected dynamically at runtime?
  Extend: Add a command without changing the dispatcher, then evaluate whether
  the design is actually easier to test and maintain.

C11 EXCEPTIONS
  Predict: Which method detects the problem and which method should recover?
  Explain: What evidence in the stack trace identifies the failing operation?
  Extend: Compare skip-record, use-default, retry, and terminate strategies.

FINAL SYNTHESIS
  Select one early program and refactor it using later concepts. State the
  problem, defend each design change, and provide tests that could disprove
  your claim that the new version is better.
